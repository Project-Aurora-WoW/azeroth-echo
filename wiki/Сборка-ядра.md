# Сборка ядра

Компиляция `worldserver` и `authserver` из исходников с модулями проекта.

## Требования

| Компонент | Проверенная версия | Путь |
|---|---|---|
| Visual Studio Build Tools | 18 (2026), MSVC 19.51 | `C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools` |
| CMake | 4.5.0 | `C:\Program Files\CMake\bin` |
| Boost | 1.78.0 | `C:\local\boost_1_78_0` |
| OpenSSL | 4.0.3 | `C:\Program Files\OpenSSL-Win64` |
| MySQL client libs | 8.0.46 | `libmysql.dll` |

Ядро требует MSVC **19.24+** — проверка встроена, при меньшей версии CMake остановится.

## Структура

```
E:\azeroth\            ← исходники (azeroth-echo-core)
E:\acbuild\            ← каталог сборки (вне исходников)
E:\acbuild\bin\RelWithDebInfo\
    ├── worldserver.exe
    ├── authserver.exe
    ├── configs/
    └── data/
```

Каталог сборки **всегда отдельно** от исходников — иначе мусор попадает в git и усложняет переключение конфигураций.

## Конфигурация

```powershell
cmake -S E:/azeroth -B E:/acbuild `
      -G "Visual Studio 18 2026" -A x64 `
      -DCMAKE_INSTALL_PREFIX=E:/acbuild/bin `
      -DSCRIPTS=static
```

Ключевые параметры:

| Параметр | Значение | Что делает |
|---|---|---|
| `-G` | `Visual Studio 18 2026` | генератор, мульти-конфиг |
| `-A` | `x64` | обязателен для 64-бит |
| `CMAKE_INSTALL_PREFIX` | `E:/acbuild/bin` | куда ставить бинарники |
| `SCRIPTS` | `static` | скрипты вкомпилированы, без DLL |

При успехе CMake выводит:

```
* Modules configuration (static):
  |   +- worldserver
  |   +- echo-challenge-modes
  |   +- mod-archivist-chronicle-of-azeroth
  |   +- mod-campaign
  |   +- mod-echoes-architecture
  |   +- mod-stranniki-iz-niotkuda
-- Configuring done
-- Generating done
```

Если модуля нет в этом списке — CMake его не нашёл. Проверить структуру: `modules/<имя>/src/*.cpp`.

## Сборка

```powershell
cmake --build E:/acbuild --config RelWithDebInfo --target worldserver authserver --parallel
```

Длительность: чистая сборка — около 20 минут на i5-9400F, инкрементальная правка одного модуля — минуты.

Результат:

```
worldserver.vcxproj -> E:\acbuild\bin\RelWithDebInfo\worldserver.exe
authserver.vcxproj -> E:\acbuild\bin\RelWithDebInfo\authserver.exe
```

## Конфигурации

| Конфигурация | Размер `worldserver.exe` | Когда |
|---|---|---|
| `Debug` | больше, медленнее | отладка кода |
| `RelWithDebInfo` | 35–37 МБ + PDB 380 МБ | **рабочая** |
| `Release` | минимум | продакшн |

`RelWithDebInfo` выбран, потому что даёт полный стек в крэш-дампе. `Crashes/*.txt` содержит имена функций и номера строк.

## Обязательные после сборки файлы

В `bin/RelWithDebInfo/` должны появиться или быть скопированы:

| Файл | Откуда |
|---|---|
| `libmysql.dll` | из MySQL |
| `libcrypto-4-x64.dll`, `libssl-4-x64.dll` | из OpenSSL |
| `libcrypto-3-x64.dll`, `libssl-3-x64.dll` | из OpenSSL (для совместимости) |
| `legacy.dll` | из старой сборки |
| `configs/` | из контентного репозитория |
| `data/dbc`, `data/maps`, `data/vmaps` | из клиента |

Без `libmysql.dll` сервер не стартует с `Не найден указанный модуль`.

## Типичные ошибки

### `LNK2019: неразрешенный внешний символ Add<...>Scripts`

Имя функции в модуле не совпадает с тем, что сгенерировал CMake.

```powershell
# посмотреть, что ожидается
Get-Content E:\acbuild\modules\gen_scriptloader\static\ModulesLoader.cpp | Select-String "Scripts"
```

Правило: `Add` + имя папки **как есть** + `Scripts`. Для папки `echo-challenge-modes` — `Addecho_challenge_modesScripts`.

### `error C3668: метод со спецификатором "override" не переопределяет`

Сигнатура хука не совпадает с ядром. Проверить в `src/server/game/Scripting/ScriptDefines/PlayerScript.h`:

```powershell
Select-String -Path E:\azeroth\src\server\game\Scripting\ScriptDefines\PlayerScript.h `
              -Pattern "OnPlayerResurrect"
```

Известный случай: `bool& applySickness` (по ссылке), а не `bool`.

### `ACCESS_VIOLATION` в `ScriptRegistry<...>::_checkMemory` на старте

Скрипты созданы глобальными объектами и регистрируются до инициализации ядра. Перенести создание внутрь функции `Add<...>Scripts()`.

### `Could not find a proper repository signature`

В `.git` нет тегов. Не критично — версия будет `unknown 1970-01-01`:

```
* AzerothCore revision : unknown 1970-01-01 ... (Archived branch)
```

Влияет только на вывод `server info`.

### `CMake Error: Unknown argument -E:\azeroth`

Опечатка: путь к исходникам без флага. Правильно `-S E:/azeroth` или просто последним аргументом без дефиса.

## Проверка сборки

```powershell
# какие модули реально слинкованы
$exe = "E:\acbuild\bin\RelWithDebInfo\worldserver.exe"
$bytes = [System.IO.File]::ReadAllBytes($exe)
$text = [System.Text.Encoding]::ASCII.GetString($bytes)
foreach ($m in "Archivist","Campaign","Echoes","Stranniki","AiBots","Cursed") {
    "$m : " + ([regex]::Matches($text, $m)).Count
}
```

Ненулевые счётчики у первых четырёх и нули у последних двух — сборка корректна.

## Запуск после сборки

```powershell
cd E:\acbuild\bin\RelWithDebInfo
.\worldserver.exe -c configs/worldserver.conf
```

Признак успеха:

```
WORLD: World Initialized In 0 Minutes 10 Seconds
worldserver-daemon ready...
```

## Как пересобрать только изменённый модуль

```powershell
cmake --build E:/acbuild --config RelWithDebInfo --target modules
cmake --build E:/acbuild --config RelWithDebInfo --target worldserver
```

MSBuild пересоберёт `modules.lib` и перелинкует `worldserver`. Заголовочные файлы ядра не трогаются, поэтому быстро.
