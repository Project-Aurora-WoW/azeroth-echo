# Устранение неполадок

Реальные проблемы, встреченные при развёртывании, и как они решались.

## Сервер

### Сервер выходит с кодом 0 сразу после старта

**Симптом в консоли:**

```
Log::CreateAppenderFromConfig: Unknown type '4' for appender Console
Error while configuring Appender Console in Logger root. Appender does not exist
AC>
```

**Причина:** `Appender.Console` в конфиге начинается с `4` (неизвестный тип).

**Решение:** первое число — тип appender, допустимо `1`:

```ini
Appender.Console = 1,4,0,"1 9 3 6 5 8"
```

### `Config::LoadFile: Failed open file 'worldserver.conf'`

**Причина:** `worldserver.exe` ищет конфиг в текущем каталоге, а он лежит в `configs\`.

**Решение:** запускать с флагом:

```powershell
.\worldserver.exe -c configs/worldserver.conf
```

### `StartNetwork failed to bind socket acceptor` / `Failed to initialize network`

**Причина:** отсутствует `data/sql`. Ядро пытается применить автообновления, падает на инициализации и не доходит до сети.

**Решение:** скопировать каталог `data/sql` из апстрима AzerothCore:

```powershell
git clone --depth 1 https://github.com/azerothcore/azerothcore-wotlk.git C:\temp\ac
Copy-Item -Recurse C:\temp\ac\data\sql E:\azeroth\data\
```

### `Applying of file '...' to database 'echo_world' failed!`

**Пример:**

```
ERROR 1062 (23000) at line 49: Duplicate entry '991001' for key 'creature.PRIMARY'
Applying of file '.../archivist_tables.sql' to database 'echo_world' failed!
```

**Причина:** изменился хеш файла миграции модуля, ядро пытается применить её повторно.

**Решение:** обновить хеш в таблице `updates`:

```powershell
$sha1 = (Get-FileHash <путь к .sql> -Algorithm SHA1).Hash
```

```sql
UPDATE echo_world.updates SET hash='<SHA1>' WHERE name='archivist_tables.sql';
```

### `Unknown column 'team' in 'field list'`

**Причина:** модуль `mod-ai-bots` требует колонку, которой нет в таблице, созданной другим модулем или версией ядра.

**Решение:** модуль не относится к проекту — удалить из `modules/` и из `configs/modules/`, переконфигурировать CMake.

### `Script named '<имя>' is assigned in the database, but has no code!`

**Причина:** в БД есть `ScriptName`, но соответствующего C++ класса нет в собранном `worldserver`.

**Решение:** либо скомпилировать модуль, реализующий скрипт, либо убрать `ScriptName` из БД:

```sql
UPDATE echo_world.gameobject_template SET ScriptName='' WHERE entry=705605;
```

### Крэш `ACCESS_VIOLATION` в `ScriptRegistry<...>::_checkMemory`

**Симптом:** `worldserver` падает за секунды, в `Crashes/*.txt`:

```
Exception code: C0000005 ACCESS_VIOLATION
ScriptRegistry<WorldScript>::_checkMemory+29
WorldScript::WorldScript+D3
`dynamic initializer for 'ChallengeModesWorldScriptInstance''
```

**Причина:** скрипты созданы глобальными объектами — их конструкторы выполняются до инициализации `ScriptRegistry`.

**Решение:** перенести создание внутрь функции-загрузчика:

```cpp
void Addecho_challenge_modesScripts()
{
    static bool registered = false;
    if (registered) return;
    registered = true;
    new ChallengeModesWorldScript();
    // ...
}
```

### `Creature (Entry: N) lists non-existing CreatureDisplayID id (M)`

**Причина:** модель из `creature_template_model` отсутствует в клиентском `CreatureDisplayInfo.dbc`.

**Решение:** подставить существующий ID. Проверить наличие в клиентском DBC — прочитать его питоном или через WDBX Editor, затем:

```sql
UPDATE echo_world.creature_template_model
SET CreatureDisplayID = <существующий>
WHERE CreatureID = <entry>;
```

### Сервер не видит БД после смены конфига

В логе при остановке видно, какие пулы открывались:

```
Closing down DatabasePool 'echo_world' ...
```

Если там `1acore_world_new` или другое имя — конфиг не применён. Проверить:

```powershell
Select-String -Path configs\worldserver.conf -Pattern "DatabaseInfo"
```

## Клиент

### Титул не отображается

**Возможные причины:**

1. Не очищен `Cache/WDB` — клиент читает старый `CharTitles.dbc`.
2. Титул не выдан: `SELECT * FROM echo_characters.character_titles WHERE guid=<guid>;`
3. ID 178 вне штатного диапазона 1–47, маска не сработала.

**Решение:**

```powershell
Remove-Item -Recurse -Force "C:\WoW\Cache\WDB\ruRU"
```

Если не помогло — пересобрать `patch-x.mpq` с ID в диапазоне 1–47.

### Маунт не призывается

1. Спелл 70010 в клиенте: проверить `verify_mpq.py` — должно быть `70010 present: True`.
2. Спелл на сервере: `SELECT * FROM echo_world.spell_dbc WHERE ID=70010;`
3. Привязка к предмету: `SELECT spellid_1 FROM echo_world.item_template WHERE entry=70003;` — должно быть `70010`.

### Карта 5000: дисконнект или «map not found»

1. `patch-Z.mpq` в `Data/`?
2. Порядок загрузки: `patch-Z` последний по алфавиту?
3. `Map.dbc` на сервере в `data/dbc/`?
4. `Map.dbc` **не** продублирован в `patch-x.mpq`?

### Аддон не появился в списке

Проверить структуру: `.toc` должен лежать прямо в `AddOns/AzerothEcho/`, а не в `AddOns/AzerothEcho/AzerothEcho/`:

```powershell
Test-Path "C:\WoW\Interface\AddOns\AzerothEcho\AzerothEcho.toc"
```

### Клиент падает на загрузке

Битый MPQ или конфликт. Быстрая проверка — убрать патчи:

```powershell
Move-Item "C:\WoW\Data\patch-x.mpq" "C:\WoW\Data\patch-x.mpq.off"
Move-Item "C:\WoW\Data\patch-Z.mpq" "C:\WoW\Data\patch-Z.mpq.off"
```

Если клиент запускается — возвращать по одному, чтобы найти виновника.

## Базы данных

### `Unknown column 'InhabitType' in 'field list'`

Миграция написана под другую схему ядра. Использовать `sql/world-adapted/`, не `sql/world/`.

### `Out of range value for column 'subclass'`

`subclass` объявлен `tinyint unsigned`, а миграция пишет `-1`. Заменить на `0`.

### `Duplicate entry '<guid>' for key 'creature.PRIMARY'`

Повторное применение миграции, создающей спавны с фиксированными `guid`. Удалить конфликтующие записи перед повторной заливкой:

```sql
DELETE FROM echo_world.creature WHERE guid BETWEEN 7000101 AND 7000102;
```

### `Table 'echo_characters.item_template' doesn't exist`

Миграция пишет не в ту базу. `item_template` живёт в `echo_world`, а не в `echo_characters`.

### Кастомные записи исчезли после заливки дампа

Дамп базового мира перезаписал таблицы. Порядок должен быть: схема → базовый ACDB → миграции проекта. Если кастом пропал — применить `sql/world-adapted/` повторно.

## SOAP

| Симптом | Решение |
|---|---|
| `HTTP 401 Unauthorized` | проверить логин/пароль аккаунта и `gmlevel >= 3` |
| `Command can not be empty` | тег `<command>` без префикса `ns1:` |
| `User has to be assigned on all realms` | `account_access.RealmID = -1` |
| Порт закрыт | `SOAP.Enabled = 1` и рестарт |

## Инструменты

### Ladik's MPQ Editor ничего не делает

CLI не поддерживается: `script`, `/console`, stdin — всё завершается с кодом 0 без результата. Это GUI-приложение. Использовать `tools/dbc/build_mpq.py`.

### PowerShell: «Отсутствует закрывающий знак )»

Скрипт в UTF-8 **без BOM**, PowerShell 5.1 читает как ANSI и ломается на кириллице.

**Решение:** сохранить с BOM:

```powershell
$content = Get-Content script.ps1 -Raw -Encoding UTF8
[System.IO.File]::WriteAllText("$PWD\script.ps1", $content, [System.Text.UTF8Encoding]::new($true))
```

### `git push` отклонён из-за размера файла

GitHub не принимает файлы крупнее 100 МБ. Добавить в `.gitignore`:

```
data/sql/
*.mpq
*.pdb
```

## Как читать крэш-дамп

Каталог `Crashes/` рядом с `worldserver.exe`. Два файла на падение: `.dmp` (для WinDbg) и `.txt` (читаемый).

В `.txt` важна секция `Call stack` — сверху вниз от точки падения:

```
00007FF7A7B18ED9  ScriptRegistry<WorldScript>::_checkMemory+29  ScriptMgr.h line 932
00007FF7A7B17F73  ScriptRegistry<WorldScript>::AddScript+53      ScriptMgr.h line 802
00007FF7A70718D3  `dynamic initializer for 'ChallengeModesWorldScriptInstance'
```

Первая строка с именем **нашего** файла — место проблемы. Здесь: статическая инициализация скрипта.

## Логи

`worldserver` пишет в консоль. Файловых логов нет, пока не настроен appender:

```ini
Appender.Server = 2,5,0,Server.log,w
Appender.Errors = 2,2,0,Errors.log,w
Logger.root     = 2,Console Server
```

Перехват вывода в файл:

```powershell
.\worldserver.exe -c configs/worldserver.conf > ws.log 2>&1
```

Кодировка лога — **cp1251**, читать с явным указанием:

```powershell
Get-Content ws.log -Encoding Default
```
