# Клиентские патчи

Как собраны `patch-x.mpq` и `patch-Z.mpq` и почему именно так.

## Зачем нужны патчи

Сервер может выдать персонажу титул 178 или спелл 70010, но клиент 3.3.5a отрисует только то, что есть в его DBC-файлах. Патч-MPQ подменяет эти файлы на изменённые.

Затрагиваются:

| DBC | Что внутри | В каком патче |
|---|---|---|
| `CharTitles.dbc` | титул ID 178 | `patch-x.mpq` |
| `Spell.dbc` | спелл 70010 | `patch-x.mpq` |
| `Map.dbc` | карта ID 5000 | `patch-Z.mpq` |

## Формат MPQ

Клиент WoW использует формат MPQ (MoPaQ) версий до v3 включительно. Сборка — формат **v1** с секторами по 4 КБ и zlib-сжатием:

```
[32 байта заголовок]
hash table    (1024 записи × 16 байт, зашифрована)
block table   (по числу файлов × 16 байт, зашифрована)
данные        (по секторам, каждый сжат отдельно)
```

Структура заголовка:

```c
struct MPQHeader {          // 32 байта
    char  magic[4];         // "MPQ\x1A"
    uint32 headerSize;      // == 32
    uint32 archiveSize;     // == размер файла
    uint16 formatVersion;   // 1
    uint16 sectorSizeShift; // 12 → 4 КБ
    uint32 hashTablePos;    // смещение хеш-таблицы
    uint32 blockTablePos;   // смещение block-таблицы
    uint32 hashTableSize;   // 1024
    uint32 blockTableSize;
};
```

Шифрование таблиц — по алгоритму StormLib: ключ вычисляется из имени компонента (`"(hash table)"`, `"(block table)"`) через хеш-функцию с таблицей из 1280 значений, затем данные «закручиваются» на 32-битном ключе.

## Почему свой сборщик

**Ladik's MPQ Editor не работает в неинтерактивном режиме.** Проверено всеми способами:

| Способ | Результат |
|---|---|
| `MPQEditor.exe script file.txt` | выход с кодом 0, ничего не делает |
| `MPQEditor.exe /console` | то же |
| stdin с командами | то же |
| `-help`, `/?` | печатает справку |

Это GUI-приложение, которому нужно окно. Для сборки в скрипте не годится.

Написан свой сборщик на Python: `struct` + `zlib` из стандартной библиотеки, без внешних зависимостей.

## Инструменты

Все в каталоге `tools/dbc/`:

| Скрипт | Что делает |
|---|---|
| `patch_chartitles.py` | добавляет титул 178 в `CharTitles.dbc` |
| `patch_spell.py` | клонирует спелл 45991 в 70010 в `Spell.dbc` |
| `build_mpq.py` | собирает `patch-x.mpq` из двух DBC |
| `build_z.py` | собирает `patch-Z.mpq` из карт |
| `verify_mpq.py` | распаковывает архив и сверяет размеры |
| `reitems.py` | извлекает записи предметов из SQL-миграций |

## Особенности работы с DBC

### Строковый блок лежит в конце файла

Смещения строк отсчитываются **от начала строкового блока**, а не от начала файла:

```
WDBC header (20 байт)
records     (records × recordSize)
stringIDs   (records × 4 байта)
string block
```

Проверка: `20 + records×recordSize + stringBlockSize == размер файла`. Если не сходится — структура понята неверно.

### `CharTitles.dbc`: 37 полей, запись 148 байт

| Индекс | Поле |
|---|---|
| 0 | ID |
| 1 | Name (основное имя) |
| 10 | TitleMask_int1 (по факту — step-индекс UI) |
| 11 | TitleMask_int2 (всегда 0) |
| 27 | Name_lang ruRU |
| 36 | NextTitle |

Строка «Хранитель Эха %s» получает `%s` как плейсхолдер имени персонажа — это штатное поведение клиента для титулов.

### `Spell.dbc`: 234 поля, запись 936 байт

| Индекс | Поле |
|---|---|
| 0 | ID |
| 4 | Attributes |
| 136 | SpellName (enUS) |

ruRU-слота для имени спелла в структуре **нет** — только enUS. Поэтому 70010 в игре называется `Summon: Voidrest Pegasus`, а не «Призыв: Бездна-Пегас».

### База для `patch-x`

`Spell.dbc` берётся из **Patch-T** (49 113 266 б, 49 994 записи), а не из серверной сборки ACDB (48 968 120 б, 49 839). Разница — 155 кастомных спеллов 69900+, которые использует проект. Если взять серверную базу, эти спеллы пропадут из клиента.

## Проверка результата

```bash
python tools/dbc/verify_mpq.py
```

Для `patch-x.mpq` ожидается:

```
hdr size=32 arc=4120622 ver=1 shift=12
hash entries: 3
CharTitles.dbc: извлечено=28053  исходник=28053  побайтово=True
Spell.dbc:      извлечено=49114265 исходник=49114265 побайтово=True
Spell: 70010 present: True
      70010 name = 'Summon: Voidrest Pegasus'
```

## Ограничения

Проверка распаковкой доказывает целостность контейнера, но не игровое поведение. Что клиент примет титул 178 и нарисует маунта — покажет только вход в игру.
