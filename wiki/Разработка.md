# Разработка

Как вносить изменения в проект и не ломать существующее.

## Рабочий процесс

```
1. Правка в azeroth-echo (контент)
        │
        ├─ SQL   → применить → reload / рестарт
        ├─ Lua   → reload eluna
        ├─ модуль → копировать в azeroth-echo-core → пересборка → рестарт
        └─ клиент → пересборка MPQ → релиз → обновление у игроков
```

Правило: **сначала контент, потом ядро**. Контент меняется часто и дёшево, ядро — редко и дорого.

## Куда что добавлять

| Хочу добавить | Куда |
|---|---|
| НПС, предмет | новая миграция в `sql/world/` + пересобрать `world-adapted/` |
| Логику на Lua | новый файл в `lua_scripts/` |
| C++ поведение | модуль в `modules/` → копия в ядро |
| Клиентский контент | DBC → `tools/dbc/` → пересборка MPQ |
| Элемент интерфейса | `addons/AzerothEcho/` |
| Документацию | `docs/` или эта wiki |

## Правила для SQL

### Нумерация

Следующая миграция — `0022`, затем `0023`. Не вставлять в середину: порядок применения задаётся именем файла.

### Идемпотентность

Каждая миграция должна применяться повторно без ошибок:

```sql
DELETE FROM `creature_template` WHERE `entry` = 70200;
INSERT INTO `creature_template` (...) VALUES (...);
```

Пара `DELETE` + `INSERT`, а не `INSERT` в одиночку.

### Заголовок

```sql
-- ============================================================
-- Migration: 0022_my_feature.sql
-- Назначение: что именно делает
-- СХЕМА: AzerothCore 3.3.5a — какие особенности схемы учтены
-- База: echo_world (или echo_characters)
-- ============================================================

SET NAMES utf8mb4;
USE `echo_world`;
```

`SET NAMES utf8mb4` обязателен — иначе кириллица в именах НПС превратится в мусор.

### Схема этого ядра

Перед написанием проверить фактическую схему:

```sql
SHOW COLUMNS FROM echo_world.creature_template;
```

Что отличается от типовых гайдов AzerothCore:

| Ожидается | В этом ядре |
|---|---|
| `creature.id1` | `creature.id` |
| `creature_template.InhabitType` | **нет** |
| `creature_template.minhealth/maxhealth` | **нет**, HP через `HealthModifier` |
| `creature.curpower` | **нет** |
| `item_template.StatsCount` | **нет**, есть `stat_type1..10` |
| `spell_dbc.SpellNameLang` | **нет**, есть `Name_Lang_enUS`/`_ruRU` |

### Проверка перед применением

```sql
-- на существующей базе посмотреть, есть ли записи
SELECT COUNT(*) FROM echo_world.creature_template WHERE entry = 70200;
```

Если таблица имеет 138 колонок, не проверять их список через `GROUP_CONCAT` — он обрезает вывод на 1024 байтах и даёт ложную картину. Использовать построчный вывод:

```sql
SELECT COLUMN_NAME FROM information_schema.columns
WHERE table_schema='echo_world' AND table_name='item_template'
ORDER BY ORDINAL_POSITION;
```

## Правила для Lua

- Кодировка **UTF-8 без BOM**
- Имя файла с числовым префиксом задаёт порядок загрузки: `23_MyFeature.lua`
- Зависимости грузить раньше зависимых
- Не полагаться на `SetTitle` — в некоторых сборках ALE метод называется `LearnTitle`

Проверка синтаксиса без запуска сервера:

```powershell
luac -p lua_scripts\23_MyFeature.lua
```

Если `luac` нет — проверить на сервере: ошибки Lua пишутся в лог `worldserver`.

## Правила для модулей

### Структура

```
modules/mod-mymod/
├── conf/
│   └── mod_mymod.conf.dist
├── src/
│   ├── MyMod.cpp
│   └── MyMod.h
└── README.md
```

`CMakeLists.txt` внутри не нужен — ядро генерирует его само.

### Точка входа

```cpp
void Addmod_mymodScripts()
{
    static bool registered = false;
    if (registered) return;
    registered = true;

    new MyWorldScript();
}
```

Имя = `Add` + имя папки без преобразования + `Scripts`. Скрипты создавать **внутри**, не глобально.

### Синхронизация в ядро

```powershell
Copy-Item -Recurse -Force E:\azeroth-echo\modules\mod-mymod E:\azeroth\modules\
cmake -S E:/azeroth -B E:/acbuild -G "Visual Studio 18 2026" -A x64
cmake --build E:/acbuild --config RelWithDebInfo --target worldserver
```

### Конфиг

`.conf.dist` копируется в `configs/modules/<имя>.conf` при конфигурации CMake. Если файл не появился — модуль не найден сборкой.

## Правила для клиентских патчей

### Порядок

```
1. Изменить DBC скриптом в tools/dbc/
2. Собрать MPQ
3. Проверить распаковкой (verify_mpq.py)
4. Обновить client/manifest.json (sha256 + size)
5. Выпустить релиз
6. Игрок обновляет через лаунчер или вручную
```

### Критично: `Map.dbc` только в `patch-Z`

Любой DBC, который есть в нескольких патчах, полностью перекрывается последним по алфавиту. Дублирование `Map.dbc` в `patch-x` приведёт к тому, что карты из `patch-x` исчезнут.

### Проверка перед релизом

```bash
python tools/dbc/verify_mpq.py
```

Ожидаемо: все блоки распакованы, размеры совпадают, `побайтово=True`.

## Коммиты

Формат: `<область>: <краткое описание>`

```
sql: миграция 0022 — НПС торговца в Морзе
lua: исправлена выдача титула в Campaign3
modules: echo-challenge-modes — сигнатура OnPlayerResurrect
client: ссылки на релиз v1.0.0 в манифесте
docs: раздел про SOAP в wiki
```

В теле — **почему**, а не что. Что видно из диффа, почему — нет.

## Что не коммитить

`.gitignore` уже исключает:

| Шаблон | Почему |
|---|---|
| `*.mpq`, `*.MPQ` | собираются из DBC |
| `*.exe`, `*.dll`, `*.pdb` | артефакты сборки |
| `data/` | карты и DBC, гигабайты |
| `*.log`, `Crashes/` | отладочный мусор |
| `configs/*.conf` | содержат пароли БД |

Проверить перед коммитом, что секретов нет:

```powershell
git diff --cached | Select-String -Pattern "password|PASS;|root;root|ghp_|sk-"
```

## Тестирование

### Без клиента

```powershell
# сервер отвечает
soap "server info" "USER" "PASS"

# контент загружен
soap "lookup item Печать" "USER" "PASS"      # → 70002
soap "lookup creature Портальный" "USER" "PASS"  # → 70001
soap "lookup spell Voidrest" "USER" "PASS"   # → 70010
soap "lookup title Echo" "USER" "PASS"       # → 178
```

### С клиентом

Только вручную:

```
.additem 70002                      → проверить титул в списке
.additem 70003                      → призвать маунта
.go xyz -13950 2877 9 5000          → карта 5000
```

Чек-лист приёмки — `docs/testing-plan.md` в репозитории.

### Что нельзя проверить автоматически

- Рендер карты, коллизии, навигация
- Отображение кастомного титула
- Модели существ в мире
- Работа аддона
- Поведение клиента на кастомных ID

Это проверяется только живым входом.

## Схема релиза

```
1. Собрать артефакты
2. Посчитать SHA256
3. Обновить manifest.json (sha256, size, url)
4. Создать тег vX.Y.Z
5. Создать GitHub Release
6. Загрузить assets
7. Скачать обратно и сверить хеши
8. Только потом сообщать игрокам
```

Пункт 7 обязателен: он ловит повреждённую загрузку до того, как о ней узнают пользователи.

## Полезные команды

```powershell
# перезагрузить всё без рестарта
soap "reload all" "USER" "PASS"

# перезагрузить Lua
soap "reload eluna" "USER" "PASS"

# статистика сервера
soap "server info" "USER" "PASS"

# состояние репозиториев
git -C E:\azeroth-echo status -sb
git -C E:\azeroth status -sb
git -C E:\azeroth-echo log --oneline -5
```
