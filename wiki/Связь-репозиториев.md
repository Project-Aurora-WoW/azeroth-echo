# Связь репозиториев

Проект «Эхо Пустоты» живёт в двух репозиториях. Они не дублируют друг друга — у каждого своя роль.

```
┌─────────────────────────────────┐      ┌──────────────────────────────────┐
│  Project-Aurora-WoW/azeroth-echo     │      │  Project-Aurora-WoW/azeroth-echo-core │
│  КОНТЕНТ                        │      │  ЯДРО                            │
│                                 │      │                                  │
│  sql/world/                     │      │  src/            (AzerothCore)   │
│  sql/world-adapted/             │ ───► │  deps/                           │
│  lua_scripts/                   │      │  modules/                        │
│  modules/  (исходники)          │ ───► │    ├── mod-campaign              │
│  addons/AzerothEcho/            │      │    ├── mod-archivist-…           │
│  client/  (manifest, лаунчер)   │      │    ├── mod-echoes-architecture   │
│  configs/ (обезличенные)        │      │    ├── mod-stranniki-…           │
│  tools/dbc/  (сборка патчей)    │      │    └── echo-challenge-modes      │
│  docs/                          │      │                                  │
└─────────────────────────────────┘      └──────────────────────────────────┘
         │                                          │
         └──────────► РЕЛИЗ v1.0.0 ◄────────────────┘
                    patch-x.mpq
                    patch-Z.mpq
                    AzerothEcho.zip
```

## Что где лежит

| Артефакт | Репозиторий | Путь |
|---|---|---|
| SQL-миграции (исходные) | `azeroth-echo` | `sql/world/0001…0021` |
| SQL-миграции (рабочие) | `azeroth-echo` | `sql/world-adapted/` |
| Lua-скрипты сервера | `azeroth-echo` | `lua_scripts/` |
| Исходники модулей | `azeroth-echo` | `modules/echo-*/` |
| Клиентский аддон | `azeroth-echo` | `addons/AzerothEcho/` |
| Манифест и лаунчер | `azeroth-echo` | `client/` |
| Инструменты DBC/MPQ | `azeroth-echo` | `tools/dbc/` |
| Документация | `azeroth-echo` | `docs/` |
| Код ядра | `azeroth-echo-core` | `src/`, `deps/` |
| Встроенные модули | `azeroth-echo-core` | `modules/` |

## Как попадают модули в ядро

Модуль существует в двух местах намеренно:

1. **`azeroth-echo/modules/`** — источник правды. Здесь модуль редактируется, обсуждается, версионируется вместе с SQL и Lua, которые от него зависят.
2. **`azeroth-echo-core/modules/`** — рабочая копия, вкомпилированная в ядро. CMake находит её автоматически по структуре каталога (`<модуль>/src/*.cpp`).

Синхронизация простая — копирование:

```powershell
# из контентного репо в ядро
Copy-Item -Recurse -Force E:\azeroth-echo\modules\echo-challenge-modes E:\azeroth\modules\
```

Затем пересобрать CMake и `worldserver`:

```powershell
cmake -S E:/azeroth -B E:/acbuild -G "Visual Studio 18 2026" -A x64
cmake --build E:/acbuild --config RelWithDebInfo --target worldserver
```

## Как ядро узнаёт о модуле

CMake сканирует `modules/*/src/` и генерирует загрузчик:

```
E:\acbuild\modules\gen_scriptloader\static\ModulesLoader.cpp
```

В нём объявляется внешняя функция вида `Addecho_challenge_modesScripts()`, а имя складывается из папки модуля **без** преобразования регистра:

| Папка | Ожидаемая функция |
|---|---|
| `mod-campaign` | `Addmod_campaignScripts()` |
| `echo-challenge-modes` | `Addecho_challenge_modesScripts()` |
| `mod-stranniki-iz-niotkuda` | `Addmod_stranniki_iz_niotkudaScripts()` |

Если имя в коде не совпадает — линкер падает с `LNK2019: неразрешенный внешний символ`. Это самая частая ошибка при добавлении модуля.

## Как контент влияет на ядро

SQL-миграции пишут в таблицы, которые ядро читает при старте:

| Миграция | Пишет в | Влияет на |
|---|---|---|
| `0001` | `creature_template`, `creature` | спавн НПС |
| `0004`, `0006`, `0008` | `item_template` | предметы и награды |
| `0018` | `spell_dbc`, `creature_template_model` | спеллы и модели |
| `0019` | `gameobject_template`, `gameobject` | Алтарь Испытаний |
| `0020` | `realm_store_*` | магазин |

Поэтому порядок такой: **сначала миграции → потом рестарт `worldserver`**. Ядро кэширует справочники в памяти.

## Клиентские патчи — отдельный слой

`patch-x.mpq` и `patch-Z.mpq` собираются из DBC скриптами из `tools/dbc/` и публикуются релизом. Они не связаны с ядром напрямую, но должны совпадать с серверными записями:

| Клиент (DBC) | Сервер (БД) | Что должно совпадать |
|---|---|---|
| `CharTitles.dbc` ID 178 | `chartitles_dbc` ID 178 | ID титула |
| `Spell.dbc` ID 70010 | `spell_dbc` ID 70010 | ID спелла |
| `Map.dbc` карта 5000 | `Map.dbc` на сервере в `data/dbc` | ID и имя карты |

Если серверная запись есть, а клиентской нет — клиент не нарисует, сервер выдаст ошибку или дисконнект.

## Резюме

- **Контент** (`azeroth-echo`) — то, что вы меняете каждый день: SQL, Lua, скрипты, аддон, патчи.
- **Ядро** (`azeroth-echo-core`) — то, что пересобирается редко: C++-код и вкомпилированные модули.
- Правка модуля → копирование в ядро → пересборка → рестарт.
- Правка SQL/Lua → применение → `reload` или рестарт.
- Правка клиента → сборка MPQ → релиз → обновление у игроков.
