# Модули

C++ модули проекта. Часть вкомпилирована в ядро, часть существует только как исходники.

## Состав

| Модуль | В ядре | Назначение |
|---|---|---|
| `mod-campaign` | да | движок кампаний 1–4 |
| `mod-archivist-chronicle-of-azeroth` | да | Хронист Ордена, лор-архив |
| `mod-echoes-architecture` | да | каркас систем: PlayerScript, SpellScript |
| `mod-stranniki-iz-niotkuda` | да | странствующие существа |
| `echo-challenge-modes` | да | режимы испытаний, Алтарь Испытаний |
| `echo-balance` | **нет** | множители урона и здоровья |
| `echo-campaigns` | **нет** | альтернативная реализация кампаний |
| `echo-economy` | **нет** | экономика реалма |
| `echo-pve` | **нет** | PvE-активности |
| `echo-pvp` | **нет** | PvP-система |
| `echo-startup` | **нет** | стартовый сценарий |

В `azeroth-echo-core/modules/` лежат только первые пять — они скомпилированы в `worldserver.exe`. Остальные присутствуют в контентном репозитории как исходники, но в сборку не входят.

## Как модуль попадает в сборку

CMake сканирует `modules/*/src/` и находит модуль по структуре каталога:

```
modules/
└── echo-challenge-modes/
    ├── conf/
    │   └── echo-challenge-modes.conf.dist
    └── src/
        └── EchoChallengeModes.cpp
```

`CMakeLists.txt` внутри модуля **не нужен** — ядро генерирует его само через `GetModuleSourceList()` и `CollectSourceFiles()`.

### Точка входа

Генерируется строка вида:

```cpp
void Addecho_challenge_modesScripts();
```

Правило формирования: `Add` + имя папки **без преобразования регистра** + `Scripts`.

| Папка | Функция |
|---|---|
| `mod-campaign` | `Addmod_campaignScripts()` |
| `echo-challenge-modes` | `Addecho_challenge_modesScripts()` |
| `mod-stranniki-iz-niotkuda` | `Addmod_stranniki_iz_niotkudaScripts()` |

Несовпадение даёт `LNK2019: неразрешенный внешний символ` при линковке `worldserver`.

### Регистрация скриптов

Внутри функции создаются объекты скриптов:

```cpp
void Addecho_challenge_modesScripts()
{
    static bool registered = false;
    if (registered)
        return;
    registered = true;

    new ChallengeModesWorldScript();
    new altar_challenge_modes();
    new ChallengeModeHardcore();
    // ...
}
```

**Важно:** создавать скрипты **внутри** функции, а не глобальными объектами. Глобальный `new ChallengeModesWorldScript()` выполняется до инициализации `ScriptRegistry` и роняет сервер на старте:

```
Exception code: C0000005 ACCESS_VIOLATION
ScriptRegistry<WorldScript>::_checkMemory
WorldScript::WorldScript
`dynamic initializer for 'ChallengeModesWorldScriptInstance''
```

Этот крэш был воспроизведён и исправлен переносом регистрации внутрь точки входа.

## Модуль `echo-challenge-modes`

### Что делает

Открывает меню выбора режима при использовании Алтаря Испытаний (gameobject 705605).

### Классы

| Класс | Режим |
|---|---|
| `ChallengeModesWorldScript` | роутер, хранит состояния |
| `altar_challenge_modes` | GameObjectScript, меню |
| `ChallengeModeHardcore` | смерть окончательна |
| `ChallengeModeSemiHardcore` | штрафы вместо смерти |
| `ChallengeModeSelfCrafted` | запрет чужих предметов |
| `ChallengeModeItemQualityLevel` | ограничение по качеству |
| `ChallengeModeSlowXpGain` | пониженный опыт |
| `ChallengeModeVerySlowXpGain` | сильно пониженный |
| `ChallengeModeQuestXpOnly` | опыт только за квесты |
| `ChallengeModeIronMan` | без смертей и торговли |

### Хуки PlayerScript

Модуль использует хуки ядра:

```cpp
void OnPlayerGiveXP(Player*, uint32& amount, Unit*, uint8) override;
void OnPlayerLevelChanged(Player*, uint8) override;
void OnPlayerLogin(Player*) override;
void OnPlayerReleasedGhost(Player*) override;
void OnPlayerPVPKill(Player*, Player*) override;
void OnPlayerKilledByCreature(Creature*, Player*) override;
void OnPlayerResurrect(Player*, float, bool& applySickness) override;
void OnPlayerTalentsReset(Player*, bool) override;
void OnPlayerLearnSpell(Player*, uint32) override;
```

Ловушка: `OnPlayerResurrect` принимает `bool&` (по ссылке), а не `bool`. Объявление `bool applySickness` даёт:

```
error C3668: метод со спецификатором "override" не переопределяет базовый класс
error C4263: функция-член не переопределяет ни одной виртуальной функции
error C4264: нет доступного переопределения
```

### Настройка

`configs/modules/echo-challenge-modes.conf`:

```ini
ChallengeModes.Enable = 1
Hardcore.Enable = 1
Hardcore.XPMultiplier = 1
SemiHardcore.Enable = 1
```

## Модуль `mod-archivist-chronicle-of-azeroth`

Лор-архив: Хронист Ордена (НПС 70180) выдаёт записи и награды за исследование.

Файлы: `ArchivistAddon`, `ArchivistItems`, `ArchivistMgr`, `ArchivistNPC`, `ArchivistPlayerScript`, `ArchivistRewards`, `ArchivistSetup`, `ArchivistStrings`.

При старте: `Archivist module loaded (enabled: yes)`, `Archivist: locale set to 'ru'`.

**Известная проблема:** модуль агрессивно обновляет БД. Первый запуск упал на повторном применении миграции:

```
Applying of file 'archivist_tables.sql' to database 'echo_world' failed!
ERROR 1062 (23000) at line 49: Duplicate entry '991001' for key 'creature.PRIMARY'
```

Причина — изменился хеш файла миграции, ядро попыталось применить её заново. Лечится обновлением хеша в `echo_world.updates`:

```sql
UPDATE echo_world.updates
SET hash='<новый SHA1 файла>'
WHERE name='archivist_tables.sql';
```

## Вырезанные модули

Из сборки удалены четыре модуля — они не связаны с проектом и мешали запуску:

| Модуль | Почему удалён |
|---|---|
| `mod-ai-bots` | миграция требовала колонку `team`, которой нет в `game_tele`-производной таблице; падало автообновление |
| `mod-cursed-islands` | не относится к проекту |
| `mod-night-of-fallen-heroes` | не относится к проекту |
| `mod-stalker-teni-lorderona` | не относится к проекту |

После удаления из `E:\azeroth\modules` и переконфигурации CMake автообновление БД перестало падать.

## Как добавить модуль

1. Положить в `azeroth-echo/modules/<имя>/` с подкаталогом `src/`
2. Скопировать в `azeroth-echo-core/modules/<имя>/`
3. Объявить функцию `Add<имя_папки_без_изменений>Scripts()` в одном из `.cpp`
4. Создавать скрипты внутри неё, не глобально
5. Переконфигурировать CMake и пересобрать

```powershell
cmake -S E:/azeroth -B E:/acbuild -G "Visual Studio 18 2026" -A x64
cmake --build E:/acbuild --config RelWithDebInfo --target worldserver
```

6. Проверить в логе: `Using modules configuration: > <имя>.conf`
7. Проверить, что предупреждение `Script named '<имя>' is assigned in the database, but has no code!` исчезло
