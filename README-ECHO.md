## Клиентские патчи

| Файл | Состав |
|---|---|
| `patch-x.mpq` | `CharTitles.dbc` (титул 178), `Spell.dbc` (спелл 70010) на базе Patch-T |
| `patch-Z.mpq` | `Map.dbc`, `CustomMaps.wdt` + 10 `.adt` — карта 5000 |

Порядок загрузки MPQ: `patch-2` → `patch-3` → `patch-x` → `patch-Z`. `Map.dbc` живёт только в `patch-Z` — его нельзя дублировать в `patch-x`, иначе более поздний патч не перекроет карту.

## Сборка патчей

```bash
python tools/dbc/patch_chartitles.py   # титул 178 в CharTitles.dbc
python tools/dbc/patch_spell.py        # спелл 70010 в Spell.dbc (из Patch-T)
python tools/dbc/build_mpq.py          # сборка patch-x.mpq
python tools/dbc/build_z.py            # сборка patch-Z.mpq из распакованных карт
python tools/dbc/verify_mpq.py         # проверка: распаковка + сверка SHA256
```

Сборщик MPQ написан с нуля (формат v1, zlib по секторам, шифрование хеш- и block-таблиц) — Ladik's MPQ Editor в неинтерактивном режиме не работает.

## Известные ограничения

- Миграции `sql/world/` падают на схеме этого ядра (нет `InhabitType`, `minhealth`/`maxhealth`, `StatsCount`; `creature.id1` вместо `id`; `CREATE INDEX IF NOT EXISTS` не поддерживается в MySQL 8.0). Используйте `sql/world-adapted/`.
- `creaturedisplayinfo_dbc` пуста, поэтому модели НПС берутся из клиентского DBC. Часть displayid из исходных миграций в клиенте отсутствует — подставлены ближайшие по типу существа.
- Титул 178 эмпирический: штатный диапазон титулов 1–47, поведение кастомных ID за его пределами не документировано.
- `patch-Z.MPQ` в исходном репозитории custom-maps повреждён (нечитаемые таблицы); `patch-Z.mpq` здесь собран заново из распакованных `.adt`/`.wdt`/`Map.dbc`.
